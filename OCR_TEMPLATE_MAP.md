# OCR Template Map

Карта форм заказ-нарядов по текущим образцам и полям, которые нужно извлекать стабильно.

## Общая цель

Для каждого сервиса нужно отдельно фиксировать:

- как определяется профиль формы;
- где находятся `service_name`, `order_number`, `repair_date`, `plate_number`, `vin`, `mileage`;
- где находятся `work_total`, `parts_total`, `vat_total`, `grand_total`;
- как выглядит табличная часть работ и материалов;
- какие поля можно вытаскивать общими правилами, а какие только сервисным профилем.

## Антарес

- Тип формы: текстовый PDF.
- Сервис: в шапке, блок `ПОСТАВЩИК`.
- Номер документа: строка `Заказ-наряд № ... от ...`.
- Дата ремонта: в той же строке, после `от`.
- Техника: строка `Автомобиль : ... гос. номер: ... VIN: ... пробег ...`.
- Работы: секция `Выполненные работы по заказ-наряду`.
- Материалы: отдельная накладная/вторая секция.
- Итоги: `Итого работ`, `Итого материалов`, `Итого по причине обращения`, `Итого по заказ-наряду`.
- Риск: низкий. Эта форма ближе всего к текущему `default`.

## Логистика

- Тип формы: текстовый PDF.
- Сервис: в шапке, блок `ПОСТАВЩИК`.
- Номер документа: `Заказ-наряд № 000000...`.
- Дата ремонта: в строке номера и в блоке `Принят/Закрыт`.
- Техника: строка `Автомобиль : ... гос. номер ... VIN ...`.
- Работы: `Выполненные работы по заказ-наряду`.
- Материалы: `Расходная накладная к заказ-наряду`.
- Итоги: `Итого работ`, `Итого материалов`, `Итого по причине обращения`, `Итого по заказ-наряду`.
- Риск: низкий/средний. Основная задача здесь не OCR, а аккуратный разбор табличной части.

## ЛидерТрак

- Тип формы: текстовый PDF.
- Сервис: в шапке `Общество с ограниченной ответственностью "ЛидерТрак"`.
- Номер документа: строка `НАРЯД-ЗАКАЗ № ... от ...`.
- Дата ремонта: в той же строке.
- Техника: блок `Автомобиль: ... гос. номер ... VIN ... пробег ...`.
- Работы и материалы: единая таблица `Выполненные сервисные услуги и использованные материалы`.
- Итоги: `Всего по странице`, `Всего по наряд-заказу`, `Всего`.
- Риск: средний. Для total-строк нужен отдельный шаблон на три суммы в одной строке.

## СибТракСкан

- Тип формы: текстовый PDF.
- Сервис: шапка `СИБТРАКСКАН`.
- Номер документа: `ЗАКАЗ-НАРЯД № ЗСТ...`.
- Даты: отдельные поля `Дата открытия`, `Дата начала работ`, `Дата окончания работ`, `Дата закрытия`.
- Техника: блок `ТРАНСПОРТНОЕ СРЕДСТВО`.
- Работы и материалы: секции `ЗАДАНИЕ: ...`, внутри одна таблица.
- Итоги: `Итого по заданию № ...`, затем общий итог в конце документа.
- Риск: средний. Нужен профиль, который умеет агрегировать суммы по заданиям.

## Грузовые резервы

- Тип формы: текстовый PDF.
- Сервис: `Исполнитель: ... "ГРУЗОВЫЕ РЕЗЕРВЫ"`.
- Номер документа: `Заказ-наряд № ...`.
- Дата ремонта: в строке номера.
- Техника: блок `Шасси ... VIN ... г/н ...`.
- Работы: секция `Виды Работ`.
- Материалы: секция `Материалы`.
- Итоги: `Итого`, `Всего выполнено работ на сумму`, `Затрачено материалов на сумму`.
- Риск: средний. Хороший кандидат для отдельного профиля totals и line items.

## АXB

- Тип формы: скановый PDF, OCR обязателен.
- Сервис: в шапке `ПОСТАВЩИК`, название часто разорвано переносом: `АХВ Трак` / `Сервис`.
- Номер документа: `Заказ-наряд № 00000...`.
- Дата ремонта: строка номера.
- Техника: строка `ТС/Автомобиль ... гос. номер ... VIN ... пробег ...`.
- Работы: `Выполненные работы по заказ-наряду`.
- Материалы: `Расходная накладная к заказ-наряду`.
- Итоги: `Итого работ`, `Итого материалов`, `Итого по причине обращения`, `Итого по заказ-наряду`.
- Главные риски:
  - OCR разрывает название сервиса на две строки;
  - табличные суммы смешиваются с колонками `НДС`, `Скидка`, `Норма н/ч`;
  - work/parts totals часто ловятся не из строки итогов, а из середины таблицы.
- Приоритет: высокий.

## ЕТС

- Тип формы: смешанный контур.
- В выборке есть минимум два разных шаблона:
  - `ets_act`: `Акт выполненных работ`;
  - `ets_invoice`: `Счет` / `Счет-фактура`.
- Сервис: `Енисей Трак Сервис`.

### ETS Act

- Номер документа: `Акт выполненных работ № ...`.
- Дата ремонта: в строке акта.
- Техника: строка `Модель автомобиля Гос. номер № шасси Пробег...`, VIN может идти позже после `Дата приема автомобиля`.
- Работы: `Выполненные работы по акту выполненных работ`.
- Материалы: `Расходная накладная к акту выполненных работ`.
- Итоги: `Итого работ`, `Итого материалов`, `Итого по акту выполненных работ`.
- Главный риск: VIN и totals идут в сжатом текстовом потоке, без устойчивых переводов строк.

### ETS Invoice

- Номер документа: `СЧЕТ № ...` или `Счет-фактура № ...`.
- Техника: часто только внутри наименования строки ремонта, например `Ремонт а/м ... № ...`.
- Явного VIN и пробега может не быть.
- Итоги: `Итого`, `Итого НДС`, `Всего к оплате`.
- Главный риск: это не полноценный заказ-наряд, а бухгалтерская форма, поэтому extraction должен быть отдельным и более консервативным.

## Что уже сделано в коде

- Добавлены default OCR profile matchers для сервисных форм.
- Добавлены service-specific OCR rules для точного service name по проблемным профилям.
- Усилены regex для totals по актам, наряд-заказам и итоговым строкам.
- Улучшен выбор полного service name из label-based кандидата.
- Улучшен поиск VIN, когда после `VIN` идет служебный текст перед самим значением.
