Статус:
- Самый проблемный сервис на продовом OCR-стеке.
- Локально документы часто выглядят лучше из-за `vision_ocr`, но на сервере используется `tesseract`.

Что уже видно:
- По проблемному документу `вв044416.pdf` на сервере было `0 works / 1 garbage part`, после фиксов стало `9 works / 1 aggregated part`.
- При этом разбор все еще неполный: сумма распознанных работ `33105.6`, а итог работ по документу `43023.6`.
- Покрытие по нормо-часам в [AXB_LABOR_NORM_COVERAGE_REPORT.md](/Users/svetlanasamojlova/курсор/road700/AXB_LABOR_NORM_COVERAGE_REPORT.md) всего `5%`.

Замечания в работу:
- Добить серверный fallback-разбор `AXB` именно под `tesseract` для плохих сканов.
- Пересобрать аудит `AXB` не на локальном `vision`, а на серверном OCR-стеке.
- Отдельно выделить и описать локальные сервисные операции `AXB`, которые не должны сравниваться с каталогом производителя как будто это заводские коды.
- Добавить отдельный слой для прицепных и полуприцепных работ `Schmitz / TEBS / кузов / электрика / мойка / нормокомплект`.
- Для проблемных сканов завести отдельный regression set PDF, который обязательно прогонять после каждой правки.

Каких данных не хватает:
- каталога локальных кодов `AXB`;
- каталога работ по прицепам;
- еще 10-20 реальных плохих сканов `AXB` с сервера.

Приоритет: `критический`

## Грузовые резервы

- Основная проблема в пробеге.

Что уже видно:

Замечания в работу:

Каких данных не хватает:

Статус:
- Один из самых стабильных сервисов.
- Большинство документов уже текстовые и хорошо разбираются.

Что уже видно:

- Основной риск не в обычных PDF, а в редких сканах со sparse layout.

Замечания в работу:

Каких данных не хватает:
- отдельного набора плохих scanned `ЕТС` актов для серверного smoke/regression теста.

Приоритет: `низкий`
