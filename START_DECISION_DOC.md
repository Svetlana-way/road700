## 3. Критичные инварианты

Ниже решения, без которых безопасно чинить код нельзя.

### 3.1 Архив

Целевое правило:
- архивная сущность доступна для просмотра и истории;
- архивная сущность недоступна для рабочих операций;
- обход через прямой API вызов невозможен;
- frontend не должен показывать архив как рабочую сущность.

| Решение | Статус | Владелец | Комментарий |
|---|---|---|---|
| Архив = строго read-only | `Не утверждено` |  |  |
| Archive/restore только через явные actions/endpoints | `Не утверждено` |  |  |
| Архив исключается из operational flows по умолчанию | `Не утверждено` |  |  |

### 3.2 `primary/source document`

Целевое правило:
- модель связи одна и однозначная;
- циклы и двусмысленные комбинации запрещены;
- `set-primary/link/unlink/archive` не должны ломать инварианты.

| Решение | Статус | Владелец | Комментарий |
|---|---|---|---|
| У `primary/source` есть единая доменная модель | `Не утверждено` |  |  |
| Циклические состояния запрещены | `Не утверждено` |  |  |
| Исторические данные будут либо мигрированы, либо помечены отдельно | `Не утверждено` |  |  |

### 3.3 Employee workflow

Целевое правило:
- есть один целевой сквозной employee use case;
- warning/review/history/report/export не конфликтуют между собой;
- у пользователя нет тупиковых или неочевидных переходов.

Текущее зафиксированное поведение системы:
- сотрудник работает только со своими видимыми ремонтами и документами;
- подтверждение сотрудником возможно только после заполнения обязательных полей и разбора всех открытых warning/checks;
- после `employee_confirmed` ремонт остаётся предварительным и ждёт финального решения администратора;
- администратор может либо финально подтвердить ремонт, либо вернуть его в ручную проверку;
- любое изменение review-полей, техники или состава документов после `employee_confirmed` возвращает ремонт в `in_review`.

| Решение | Статус | Владелец | Комментарий |
|---|---|---|---|
| Целевой employee flow описан и технически зафиксирован | `Частично` |  | Сквозной flow покрыт regression-тестом `test_employee_workflow_runs_end_to_end_between_employee_and_admin`, а технический closeout собран в `PR24_CLOSEOUT.md` |
| Допустимые статусы и переходы по flow утверждены | `Частично` |  | Технически зафиксированы переходы `in_review -> employee_confirmed -> confirmed` и возврат `employee_confirmed -> in_review` при изменениях; формальное утверждение со стороны бизнеса ещё требуется |
| Финальная форма report/export утверждена | `Частично` |  | Технически реализованы единый итоговый отчёт, workflow-сводка и экспорт executive sections в UI/XLSX/PDF; полный sign-off пакет собран в `signoff_artifacts/2026-04-04_report-export-signoff/`, открытым остаётся reviewer verdict в `BUSINESS_SIGNOFF_REPORT_EXPORT.md` |

### 3.4 Backup / Restore

Целевое правило:
- система честно сообщает, что именно попадает в backup;
- restore не обещает лишнего;
- post-restore поведение UI согласовано с реальным результатом.

| Решение | Статус | Владелец | Комментарий |
|---|---|---|---|
| Backup contract описан без двусмысленности | `Не утверждено` |  |  |
| Restore contract описан без ложных ожиданий | `Не утверждено` |  |  |
| Post-restore сценарий frontend утвержден | `Не утверждено` |  |  |

## 5. Quality Gate

Ни один P0-фикс не считается завершенным без этих условий.

### Обязательные проверки

- backend regression tests по затронутому блоку;
- frontend `build`;
- frontend `tsc`;
- smoke по критичному пользовательскому сценарию;
- явная проверка, что фикс не нарушил архивные инварианты и права доступа.

### Статус согласования

| Решение | Статус | Владелец | Комментарий |
|---|---|---|---|
| Regression test обязателен для каждого P0 бага | `Не утверждено` |  |  |
| Backend test suite для merge определен | `Не утверждено` |  |  |
| Frontend build/typecheck для merge обязателен | `Не утверждено` |  |  |
| Smoke-gate по критичным сценариям определен | `Не утверждено` |  |  |

### Минимальный smoke-gate

- archive repair/document;
- review queue action;
- `PATCH /repairs/{id}` без потери `checks`;
- OCR/import happy path и failure path;
- password change/reset/recovery с инвалидированием старых JWT.
